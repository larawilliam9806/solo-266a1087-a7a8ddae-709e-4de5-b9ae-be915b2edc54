# 变异归一化汇总平台

同一次插入/缺失在重复序列中可能被不同样本写成不同坐标。本平台接收参考序列与
逐样本 TSV 变异文件，将等价变异按参考**左对齐归一化并去冗余**，再按规范变异
汇总多样本检出情况。

技术栈：Flask + SQLite（WAL），Docker Compose 一键启动。

## 快速启动

```bash
docker compose up -d --build
# 打开 http://localhost:8000
```

SQLite 数据文件存放在命名卷 `variant-data`（容器内 `/data/variants.db`），
重建容器不丢数据；`SECRET_KEY` 请在 `docker-compose.yml` 中替换为生产密钥。

本地开发：

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
DATABASE_PATH=/tmp/dev.db flask --app 'app:create_app()' run --debug
```

## 使用流程

1. **先上传参考序列**：一条仅含大写 `A/C/G/T` 的序列，支持纯文本或单记录 FASTA。
2. **逐样本上传 TSV**：Tab 分隔、1-based 坐标，可带表头，可填实验批次：

   ```tsv
   POS	REF	ALT	GT
   3	T	TT	0/1
   8	A	C	1/1
   ```

   - 仅接收：单碱基替换、带锚碱基的纯插入（如 `T>TT`）、带锚碱基的纯缺失（如 `TT>T`）
   - GT 仅允许 `0/1` 或 `1/1`
   - 每行先核对 REF 与当前参考是否一致，再做左对齐归一化
   - 批次选填；同名重传整体替换，**批次以本次填写为准**（未填即为未分批，不继承旧批次）
3. **按批次上传空白对照**：对照只影响同批样本的质控判定。

   - 仅含标准表头 `POS	REF	ALT	GT` 的文件代表**有效的零检出**；
     空文件或非标表头不代表零检出，直接拒绝
   - 含数据行时与样本一样做 REF 核对、归一化与重复校验
   - 每批只保留**本版参考下最后一次上传成功**的对照
   - 提交携带页面所示参考版本：参考已被换下或文件校验失败时**拒绝本次提交，
     已生效对照保持不变**
4. 首页按**规范变异**拆分统计检出样本：同批对照未检出 / 同批对照也检出 /
   缺批次或缺本版对照；点详情查看逐样本质控判定与命中对照的原始位点。

## 关键规则

### 归一化（参考左对齐）

采用经典 left-align 流程（与 `bcftools norm` / `vt normalize` 等价）：

1. 去除 REF/ALT 共同后缀；
2. 无法去尾时整体左移一位并补参考前缀碱基，循环直到不能移动；
3. 在参考起点出现空等位基因时回退到最后一个合法带锚状态；
4. 去除共同前缀（每个等位基因至少保留 1 个锚碱基）。

因此重复序列中的等价写法（如 `GCTTTGC` 上 `(3,T,TT)`、`(4,T,TT)`、`(5,T,TT)`）
都会归一化为同一个规范键 `(2,C,CT)`，从而被识别为同一变异。

### 空白对照与批次质控

- 空白对照按 `(批次, 参考版本)` 生效，**只影响同批样本**；更换参考后旧版对照不再生效，
  需按新参考重新提交，否则有批次的样本计入「缺批次或缺本版对照」。
- 首页每个规范变异的检出样本被拆成互斥三桶（之和恒等于检出总数）：
  - **对照未检出**：样本有批次且本版对照未含该变异；
  - **对照也检出**：本版对照含同一规范变异（详情页附对照的原始位点与等位基因）；
  - **缺批次或缺本版对照**：样本未分批，或本版参考下该批次还没有生效对照。
- 详情页逐样本给出质控判定：`通过` / `对照也检出`（需复核）/ `缺对照`（无法判定）。
- 所有判定基于库内当前状态实时计算：对照替换、样本换批次、参考更新后
  下一次查询即按新状态判定；对照变异在入库时已归一化存储，查询无需重读 TSV。

### 事务与一致性

- 同一样本归一化后出现重复变异（同一规范键）→ **整份文件拒绝**，不写入任何数据。
- 任何校验错误（REF 不符、非法 GT、类型不支持、格式错误等）都在事务内失败回滚，
  **错误上传不改变当前结果**（空白对照同理：失败时保留已生效对照）。
- 同名样本重传 = 替换：新文件完整校验通过后，旧变体在同一事务中删除，旧变异不再计数。
- 同批次对照重传 = 替换：每批每版参考只保留最后一次上传成功的对照。
- 更换参考 = 在一个写事务内插入新参考并**重验全部样本**：
  REF 不符或归一化后重复的样本标记为 `NEEDS_REUPLOAD`（待重传）、变体删除、
  从汇总剔除；修正后重新上传即恢复。
- 所有写事务使用 `BEGIN IMMEDIATE` 立即取 SQLite 写锁，使样本上传、对照提交与
  参考更新严格串行；页面读取使用快照事务，因此各类上传交错时，页面只会展示
  **同一版参考下的完整汇总**，不会出现跨版本混算。

## 目录结构

```
app/
  __init__.py        # Flask 工厂与路由
  normalization.py   # 纯函数：解析、校验、左对齐归一化（无 Flask 依赖）
  db.py              # SQLite 连接、WAL、事务、建表
  services.py        # 上传/重验/替换/汇总业务逻辑
  templates/         # Jinja2 页面
  static/style.css
tests/               # unittest：归一化单测、随机性质测试、端到端集成测试
docker/entrypoint.sh
Dockerfile
docker-compose.yml
```

## 测试

```bash
python -m unittest discover -s tests -v
```

- `test_normalization.py`：解析、边界、等价变异左对齐、重复拒绝等
- `test_properties.py`：4000 个随机变异，验证「单倍型保持」「同事件同规范键」
- `test_app.py`：Flask 端到端流程（上传、替换、换参考重验、错误隔离、删除）
- `test_controls.py`：空白对照（零检出、校验沿用、过期参考拒绝、三桶统计、
  逐样本质控、批次语义、并发一致性）

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 参考信息、上传表单、对照列表、样本列表、规范变异三桶汇总 |
| POST | `/reference` | 上传/更换参考（multipart 字段 `reference`） |
| POST | `/samples` | 上传/重传样本（字段 `name`、`batch`（选填）、`sample`） |
| POST | `/controls` | 提交批次空白对照（字段 `batch`、`reference_id`（页面所示参考）、`control`） |
| POST | `/samples/<id>/delete` | 删除样本 |
| GET | `/variants/<pos>/<REF>><ALT>` | 变异详情：样本、批次、GT、原始位点、质控判定、命中对照位点 |
| GET | `/healthz` | 健康检查 |
